**Status**: ✅ COMPLETE

## Overview

Phase 2 implements memory allocation and symbol definition generation for the R65 compiler's code generation backend. This phase processes MIR static declarations and emits WLA-DX assembly directives for symbol definitions.

## Components

### 1. MemoryAllocator (`memory_alloc.py`)

**Purpose**: Track and allocate memory locations for static variables.

**Key Features**:
- **Zero-Page Allocation**: Direct page (fastest access, $10-$FF)
  - Explicit addressing: `#[zeropage(0x20)]`
  - Auto-allocation: `#[zeropage]` (finds next free byte)
  - Conflict detection for overlapping allocations

- **RAM Allocation**: SNES Work RAM ($7E0000-$7FFFFF)
  - Explicit addressing: `#[ram(0x7E0000)]`
  - Auto-allocation: `#[ram]` (finds next free range)
  - Smart allocation that skips over explicit allocations

- **Hardware Register Allocation**: Memory-mapped I/O
  - Requires explicit address: `#[hw(0x2100)]`

- **ROM Allocation**: Read-only data (placeholder for future)

**Allocation Strategy**:
1. Process explicit allocations first (reserves specific addresses)
2. Process auto-allocations second (finds free spots)
3. Conflict detection prevents overlapping allocations

**Key Methods**:
```python
def allocate_zeropage(symbol, static_decl, explicit_addr=None)
def allocate_ram(symbol, static_decl, explicit_addr=None)
def allocate_hw(symbol, static_decl, hw_addr)
def allocate_rom(symbol, static_decl, explicit_addr=None)
def allocate_all(static_decls)  # Bulk allocation
```

**Type Size Calculation**:
- `u8, i8, bool` → 1 byte
- `u16, i16` → 2 bytes
- Arrays: `element_size * length`
- Structs: sum of field sizes (packed)
- Pointers: `near<T>` = 2 bytes, `far<T>` = 3 bytes

### 2. SymbolDefinitionGenerator (`symbol_gen.py`)

**Purpose**: Emit symbol definition sections in assembly.

**Generated Sections**:
1. **Constants** (`.EQU` directives)
```asm
.EQU TILE_SIZE 8
.EQU BUFFER_SIZE 256
```

2. **Zero-Page Variables** (`.DEFINE` directives)
```asm
.DEFINE TEMP $0020              ; Explicit
.DEFINE FLAGS $0010             ; Auto-allocated
```

3. **Hardware Registers** (`.DEFINE` directives)
```asm
.DEFINE INIDISP $2100           ; Screen brightness
.DEFINE HVBJOY $4212            ; VBlank/HBlank status
```

4. **RAM Variables** (`.DEFINE` directives)
```asm
.DEFINE BUFFER $7E0000          ; 256 bytes
.DEFINE SCORE $7E0100           ; Auto-allocated - 2 bytes
```

**Key Methods**:
```python
def emit_zeropage_definitions()
def emit_ram_definitions()
def emit_hw_definitions()
def emit_constant_definitions(constants)
def emit_all_definitions(constants)
```

**Comment Generation**:
- Source location tracking (when available)
- Size annotations for multi-byte allocations
- Explicit vs auto-allocated indicators


## Key Design Decisions

1. **Symbol Names as Dictionary Keys**: Used symbol names (strings) instead of Symbol objects as dictionary keys since Symbol dataclass is not hashable by default.

2. **Storage Kind Enum**: Used `StorageKind` enum values instead of strings for type safety.

3. **Smart Auto-Allocation**: Auto-allocation searches for first free spot after explicit allocations, preventing overlaps:
   - For zero-page: linear search starting from `zeropage_next`
   - For RAM: conflict detection loop that skips over used ranges

4. **Allocation Order**: Process explicit allocations before auto-allocations to reserve specific addresses first.

5. **Address Conflict Detection**:
   - Zero-page: Individual byte tracking in set
   - RAM: Range tracking with overlap detection

6. **Type Size Calculation**: Handles all HIR types including arrays, structs, and pointers.

## Known Limitations

1. **ROM Allocation**: Placeholder implementation - full support deferred to later phase
2. **Source Info Tracking**: Currently `None` - will be filled in by later phases
3. **No Gap Filling**: Auto-allocation doesn't fill gaps between allocations (always allocates at end)
